## B. `#[non_exhaustive]` 审计

### 已落地(WS-3)

对 `crates/rr-core/src/error.rs` 的 7 个对外错误 enum 全部加注;gitnexus_impact 全 LOW(d=1 调用方 0;enum match 不被图追踪,以编译为准);跨 crate 穷尽 match 仅 `crates/rr-network/src/error_convert.rs` 7 处,各加一条不可达通配臂(映射为 sanitized `Status::internal("<category> error")`,与该模块信息防泄漏规则一致,现有行为不变)。

- [x] `RrError` / `RaftError` / `StorageError` / `ConfigError` / `RouterError` / `NetworkError` / `CodecError`。
  检查:`grep -B1 '^pub enum' crates/rr-core/src/error.rs | grep -c non_exhaustive` → 7。
  编译验证:`cargo check --workspace --all-targets --features rocks` 通过。

### 评审后**不加**(本周期结论)

- [x] `BatchOp`(rr-core/storage.rs:9)— **不加**。下游 `StorageEngine` 实现者必须 match 它实现 `write_batch`;若新增 op 时靠通配臂静默忽略 = 存储层静默丢数据,编译期硬报错反而是正确行为。
- [x] `ApplyOutcome`(rr-core/idempotency.rs:166)— **不加**。wire 级 serde enum,文档明确"dispatch 层是唯一编解码端";其演进属 wire 兼容问题,由 framing/tag(`APPLY_OUTCOME_TAG`/`APPLY_OUTCOME_VERSION`)管理,不靠源码级 non_exhaustive。

### 留待 RC 评审(拿不准,本周期不动)

- [ ] `DurabilityPolicy`(rr-storage/rocks.rs:46)— 所有 match 在同 crate 内,下游主要经 config 构造;但与 deprecated alias 拆除时间线耦合(见 D 节),评审时与 alias 策略一并定。
  检查:`grep -rn 'DurabilityPolicy::' crates/ --include='*.rs' | grep -v rr-storage` → 确认无跨 crate match。
- [ ] `OutputTarget`(rr-core/output.rs:9)— 演进确定性最高(0.2.0 刚加 `KafkaPublish`,producer 抽象即扩展点);但跨 crate dispatch match 在 `rr-raft/src/output_runner.rs:201-204,265-299`,加注会削弱框架自身的穷尽检查,需评审权衡(若加,通配臂:label `"unknown"` / dispatch 返回 `RrError::Application`)。
- [ ] `IdempotencyDecision`(rr-core/idempotency.rs:94)— 框架内部决策流,下游不 match;决策空间(New/Replay/Expired/Collision)目前稳定。
- [ ] `PartitionConfig`(rr-core/types.rs:16)— serde 持久化进 etcd routing schema(A-0004),演进同时影响 on-disk/config schema,不单靠 non_exhaustive。
- [ ] `RoutingTableChange`(rr-core/config.rs:13)— watch 事件流;新增事件类型时消费者(rr-router)静默通配会导致路由更新停滞,风险方向与 BatchOp 类似。
- [ ] 其他 crate 的对外 pub enum 快速扫一遍(rr-raft/rr-network/rr-server/rr-client/rr-config* 的 pub enum 清单)。
  检查:`grep -rn '^pub enum' crates/ --include='*.rs' | grep -v rr-core`,逐一按上面同样标准(下游是否可能 match、静默通配是否危险)评审。


- [ ] `types.rs`:`NodeId`/`GroupId`/`PartitionId`/`LogIndex` 别名、`NodeAddr`、`PartitionConfig`、`GroupMeta`、`RoutingTable`。

## D. deprecated alias 保留策略(`DurabilityPolicy::Balanced`/`Fast`)

- [ ] **一致性核对(发现不一致,必须裁决)**:`rocks.rs:80-85` `#[deprecated(since = "0.3.0")]` + doc 注释"kept for one minor version … before upgrading past v0.4.0";而兼容性文档 `docs/docs/reference/compatibility.md` 的 Deprecation Process 是"grace period ≥ 一个完整 MINOR,下一个 MAJOR 删除"(pre-1.0 语义下 MINOR 即 breaking 边界)。crate 实际版本为 0.2.0(WS-3 已对齐)。
  裁决点:(a) alias 实际随哪个版本首次 deprecated——若 rename 在 0.2.0 生效,`since` 应为 `"0.2.0"`;(b) 删除版本——按 compatibility.md 应为下一个 breaking 版本(0.3.0),按代码注释则为 0.4.0。二者必须对齐,并把最终策略写回 compatibility.md(docs 归 docs 负责人,本清单只出结论)。
  检查:`grep -n 'deprecated' crates/rr-storage/src/rocks.rs`;对照 compatibility.md "弃用流程" 节。
- [ ] 全仓扫其他 `#[deprecated]` 项,确认均符合同一策略。
  检查:`grep -rn '#\[deprecated' crates/ --include='*.rs'`。
