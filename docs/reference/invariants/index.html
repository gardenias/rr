系统级不变量目录 / System Invariants

本文是 Rr 对外系统属性的登记表：每条属性必须有可判定的不变量、强制链、代码强制点 （file:line）、测试和已知缺口。

This document registers Rr's advertised system-level properties. Each property has a decidable invariant, an enforcement chain, code enforcement points (file:line), tests, and known gaps.

目的与维护 / Purpose and Maintenance​

本文随代码演进。新增一致性、投递或安全承诺前，必须先登记不变量；未登记的对外属性不视为已承诺。 2026-08-16 全量评审（.sisyphus/evidence/rr-full-review-2026-08-16.md）发现的主要根因是“不变量存在， 但某层未强制”；本登记用于显式追踪这些强制点。

This is a living document. Register new consistency, delivery, or security commitments before implementing them; unregistered properties are not advertised guarantees. The 2026-08-16 review (.sisyphus/evidence/rr-full-review-2026-08-16.md) identified a recurring root cause: an invariant existed but one layer did not enforce it. This registry makes those enforcement points explicit.

ADR（.sisyphus/adr/）记录设计决策及权衡；本文记录当前运行时承诺及执法状态。ADR 可冻结，本文必须 保持准确。

ADRs in .sisyphus/adr/ record design decisions and tradeoffs. This document records current runtime commitments and enforcement. ADRs may remain frozen; this registry must stay accurate.

维护规则 / Maintenance rules:

  1. 改动强制点时，同一 PR 更新本文的 file:line；评审者检查行号是否仍准确。

    Update file:line references in the same PR as enforcement changes; reviewers must check them.

  2. 行号基线为 HEAD = ba69cc8（2026-08 全量评审），之后靠同步更新维持准确，不保证任意历史 commit 可回溯。

    Line references use HEAD = ba69cc8 (the 2026-08 review) as their baseline and are maintained by later updates; they are not reproducible against arbitrary historical commits.

  3. 缺口须引用评审条目或 issue 及修复工作流（WS-x/R-x，见 .sisyphus/plans/rr-v0.2.0-release-roadmap.md）。

    Every gap must cite a review item or issue and its WS-x/R-x remediation workflow in that roadmap.

  4. 闭环缺口保留并注明版本，不删除历史记录。

    Keep resolved gaps with their closing version; do not erase their history.

  5. CHANGELOG Added 的能力宣称、文档中的 guarantee/must/never、带语义承诺的新 public API，均须先登记 INV 与测试。scripts/check-invariants.sh 的阻塞式 invariants-lint 和 PR 模板负责检查。

    Capability claims in CHANGELOG Added, guarantee/must/never language in docs, and new public APIs with semantic commitments all require an INV entry and tests first. The blocking invariants-lint check in scripts/check-invariants.sh and the PR template enforce this rule.

阅读约定：“不变量”是可判定承诺；“链”分配各层责任；“强制点”列出代码位置； “测试”列出证据；“缺口”区分开放问题与已闭环历史。 / Reading convention

An invariant is a decidable promise; the chain assigns layer responsibilities; enforcement points locate the code; tests provide evidence; gaps distinguish open issues from resolved history.

INV-1 Durable Append — 已 ACK 的写必存活 / Acknowledged Writes Survive​

不变量 / Invariant​

client_write 成功 ACK 的 entry，在单点进程崩溃或机器断电并重启后，必须仍存在于该节点 Raft log，或 由其产生的状态机状态/快照中；vote 必须同等级持久化以防止脑裂。

After a successful client_write ACK, the entry must survive a single-process crash or machine power loss and restart in that node's Raft log, derived state-machine state, or snapshot. Votes require equivalent durability to prevent split brain.

此承诺以 DurabilityPolicy::Strict 为前提。ReplicatedOnly/TestOnly 显式放弃单节点持久性，不在本 不变量范围内；启动时会告警。

This promise requires DurabilityPolicy::Strict. ReplicatedOnly/TestOnly explicitly give up single-node durability and are outside this invariant; startup emits a warning.

强制链 / Enforcement Chain​

  1. ClientService.request → ClientDispatchImpl::submit_write （crates/rr-server/src/dispatch.rs:77）调用 raft.client_write。

    The client request enters submit_write, which calls raft.client_write.

  2. openraft RaftCore 调用 RaftLogStorage::append，持有 IOFlushed callback；只有 io_completed(Ok) 后 entry 才可 commit/apply/ACK。

    Openraft persists through append; only io_completed(Ok) permits commit, apply, and ACK.

  3. RocksLogStorage::append 编码 BatchOp 并提交 per-group IoBatcher （crates/rr-raft/src/rocks_log_storage.rs:214-252）。

    Append submits encoded batch operations to the per-group batcher.

  4. IoBatcher 合并为一次 write_batch()，成功后才应答等待者 （crates/rr-raft/src/io_batcher.rs:188-201）。

    The batcher answers waiters only after the combined write_batch() succeeds.

  5. RocksStorage::write_batch 使用 durability.write_options() 调 db.write_opt （crates/rr-storage/src/rocks.rs:518-543）；Strict 下 WriteOptions::set_sync(true)，每次批写 伴随 WAL fsync。

    Strict sets synchronous writes, so each batch includes a WAL fsync.

  6. stop_group 停后台任务、等待在途写归零（上限 5 秒），再 raft.shutdown() （crates/rr-raft/src/group_manager.rs:359-434）。

    Shutdown stops background work, bounds the in-flight-write drain to five seconds, then shuts down Raft.

INV-2 Linearizable Read — 线性一致读 / Linearizable Reads​

不变量 / Invariant​

ReadLinearizable 的结果必须反映至少到该读发起时已完成 Raft commit 的全部写。非 Leader 不得自行作答， 必须返回 leader_id/leader_addr 重定向，由 SDK 转向 Leader 重试。

A ReadLinearizable result must reflect every write committed by Raft at least through the read's invocation. A non-leader must not answer locally; it returns leader_id/leader_addr for SDK redirect and retry.

强制链 / Enforcement Chain​

  1. ClientService.read_linearizable（crates/rr-network/src/client_service.rs:213-239；契约见 crates/rr-network/proto/client.proto:13-18）。

    The protocol exposes a distinct linearizable-read RPC.

  2. ClientDispatchImpl::submit_linearizable_read 经 ShardRouter 定位组 （crates/rr-server/src/dispatch.rs:152-159）。

    Dispatch routes the request to its group.

  3. RaftGroupManager::linearizable_read 使用 get_read_linearizer(ReadPolicy::ReadIndex) （crates/rr-raft/src/group_manager.rs:810）。

    The leader confirms quorum and obtains the commit point through ReadIndex.

  4. openraft ForwardToLeader 映射为 RaftError::NotLeader { leader, leader_addr } （group_manager.rs:813-817），dispatch 转为 proto leader_info（dispatch.rs:166-173）。

    Forwarding errors become typed leader redirects on the wire.

  5. linearizer.await_ready(&raft) 等本地 apply 越过 ReadIndex commit 点 （group_manager.rs:825-829）。

    The local state machine catches up through the ReadIndex commit point.

  6. 只有追平后才 local_read（group_manager.rs:831）。

    Only then is the local state machine read.

INV-3 Exactly-Once Ingest — 摄入恰好一次 / Exactly-Once Ingest​

不变量 / Invariant​

同一 Kafka offset 无论因换主、恢复、seek 或 at-least-once 重投而重放多少次，用户可见的 Service::handle() 效果恰好一次；重复投递返回首次执行的缓存响应。

No matter how often one Kafka offset is replayed through leadership changes, recovery, seeks, or at-least-once delivery, the user-visible Service::handle() effect occurs exactly once and duplicates return the first cached response.

去重窗口受 LRU 容量限制（默认 10 000，crates/rr-raft/src/idempotency.rs:68）。窗口外重放返回 IdempotencyExpired 并拒绝执行，属于 fail-closed，不会重复执行。

The deduplication window is LRU-bounded (default 10,000). Replays outside it return IdempotencyExpired and fail closed instead of executing again.

强制链 / Enforcement Chain​

  1. ingestor supervisor 仅 Leader poll（crates/rr-raft/src/ingestor_runner.rs:184, :345）； follower 从 Raft log 获得 entry，不各自消费 Kafka。

    Only leaders poll Kafka; followers receive the same entries through Raft.

  2. AutoIdempotency::offset_to_request_id 生成单调 request ID，与 request_type 组成 IdempotencyKey 写入 FramedEntry（ingestor_runner.rs:391-397）。

    Each offset becomes a monotonic request ID in a framed idempotency key.

  3. 整批经 write_batch 提交（:415），apply 成功后才 commit_applied 推进 offset（:434-443）。

    The batch commits through Raft before the upstream offset advances.

  4. ServiceStateMachineAdapter::apply 走 apply_keyed （crates/rr-raft/src/service_adapter.rs:355-373 → :285-350）；IdempotencyLayer::decide 分派 Replay/Collision/Expired/New（crates/rr-raft/src/idempotency.rs:107-143）。Replay 与 Collision 均返回缓存成功响应；Collision 只比较 client_id 并记录警告，不比较 payload、不拒绝；Expired 拒绝， New 执行并记录。

    Apply returns cached successful responses for Replay and Collision. Collision compares only client_id and logs a warning, without comparing payloads or rejecting; Expired rejects, while New executes and records.

  5. watermarks + LRU 随快照 capture/restore（idempotency.rs:148-160, :175-194，replace-not-merge）； 新 Leader 从 framework_state.ingestor.last_applied_offset 恢复 seek （ingestor_runner.rs:234-259）。seed 失败直接退出，禁止借 auto.offset.reset 静默从头重放 （:203-213）。

    Snapshot state restores deduplication and seek position. Seed failure stops the supervisor rather than silently replaying from earliest.

INV-4 At-Least-Once Output — 输出至少一次 / At-Least-Once Output​

不变量 / Invariant​

Service::handle_with_outputs 在已 commit 并 apply 的 entry 上产生的每个 Output 最终都会投递到目标； 失败按指数退避无限重试，水线只在成功后推进，不静默丢弃。语义为 at-least-once，换主可能重投，下游以 idempotency_key 去重。

Every Output produced by Service::handle_with_outputs for a committed and applied entry is eventually delivered. Failures retry indefinitely with exponential backoff, the watermark advances only after success, and no path silently drops output. Delivery is at-least-once: failover can redeliver, and downstream uses idempotency_key for deduplication.

强制链 / Enforcement Chain​

    Only leaders send; followers remain parked.

  3. dispatch_one 按 target 分发（:260-300）：RaftWrite 以 seq 派生幂等键，KafkaPublish 透传 idempotency_key。

    Dispatch derives idempotency for Raft writes and forwards the Kafka key.

INV-5 Snapshot Consistency — 快照一致性 / Snapshot Consistency​

不变量 / Invariant​

INV-6 Routing Transition Safety — 路由切换安全 / Routing Transition Safety​

不变量 / Invariant​

路由表更新生效后，旧 shard 不再收到该 partition 的新写；切换前已 ACK 的写由 INV-1 保证不丢；新写全部 路由到新 shard。ConfigProvider 是唯一事实源，不存在第二份调用方缓存视图。

After a routing-table update takes effect, the old shard receives no new writes for that partition. INV-1 preserves writes acknowledged before the switch, and new writes go to the new shard. The ConfigProvider is the single source of truth; callers hold no second cached view.

    MemConfigProvider::add_partition and etcd watch update the table and publish RoutingTableChange; the in-memory provider swaps copy-on-write Arc snapshots.

  2. ShardRouter::route 每请求调用 routing_table_snapshot()：mem 为读锁 + Arc clone；etcd 每次做 keys-only revision 探针，未变才用缓存，变化立即全量重扫 （crates/rr-router/src/router.rs, crates/rr-config-etcd/src/lib.rs）。

INV-9 Homogeneous Formation Safety — 组建授权与旧集群收养 / Formation Authorization and Legacy Adoption​

不变量 / Invariant​

相同 SeedSpec 下，只有 Genesis + Forming 可按完整 seed roster 初始化；Active 记录下的 pristine 本地组 只能等待复制。AdoptLegacy 首次创建记录前要求本地所有托管组已初始化，直接写入 LegacyAdopted + Active， 不得 initialize 或改变 voter/learner。后续收敛只能走显式 Job/Admin learner + change-membership。

For the same SeedSpec, only Genesis + Forming may initialize the full seed roster. A pristine local group under an Active record can only await replication. Before its first record, AdoptLegacy requires every hosted local group to be initialized, writes LegacyAdopted + Active directly, and must not initialize or change voters/learners. Later convergence uses only explicit Job/Admin learner plus change-membership flows.

SeedSpec 是初始路由/Genesis 授权，不是当前 membership；P1 不提供动态扩缩容、副本替换或 resharding。

SeedSpec authorizes initial routing/Genesis and is not current membership. P1 does not provide dynamic scaling, replica replacement, or resharding.

lifecycle store 不可用时，已初始化节点可用本地 Raft 状态继续服务，但 readiness 必须 degraded；pristine 节点必须 fail closed，不得把 store outage 当成初始化授权。

When the lifecycle store is unavailable, initialized nodes may serve from local Raft state with degraded readiness. Pristine nodes must fail closed and must not treat store outage as authorization to initialize.

强制链 / Enforcement Chain​

  1. TOML/CLI 要求完整 id@advertised_addr roster、本节点在 roster 内、非空 etcd endpoints，并拒绝 managed formation 与 bootstrap/peers 混用。

    Parsing requires a complete roster containing this node and nonempty etcd endpoints, and rejects mixed managed/legacy bootstrap configuration.

  2. FormationSupervisor::authorize_or_create 区分 Genesis/AdoptLegacy，校验本地状态、seed/origin，并通过 LifecycleStore CAS 创建唯一记录。

    Authorization validates local state and identity before creating one record through CAS.

  3. FormationSupervisor::reconcile_inner 只允许 Genesis/Forming 初始化并核对实际 seed membership； Active/pristine 返回 AwaitingReplication；AdoptLegacy 只报告现状，不调 membership API。

    Reconcile initializes only Genesis/Forming, leaves Active/pristine awaiting replication, and never changes membership during legacy adoption.

  4. managed RrNode 禁用旧 watch-loop 成员副作用与自动 promotion；readiness 要求 formed + observed leader，store outage 为 degraded/not-ready。

    Managed nodes disable legacy membership side effects and require formation plus an observed leader for readiness; store outages degrade readiness.
