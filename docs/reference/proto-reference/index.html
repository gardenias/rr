Protobuf 参考 / Protobuf Reference

Rr 使用 Protocol Buffers 定义 gRPC 通信：raft.proto 承载节点间 Raft RPC，client.proto 承载客户端 请求与读取，admin.proto 承载运维管理。protobuf 的 bytes 字段传输不透明负载；Raft 内部负载使用 bincode，业务负载可选择应用自己的编码，框架另可能添加带版本的信封。

Rr uses Protocol Buffers for gRPC: raft.proto carries inter-node Raft RPCs, client.proto carries client requests and reads, and admin.proto carries administration. Protobuf bytes fields carry opaque payloads. Raft internals use bincode; applications can choose their own payload encoding, while the framework may add versioned envelopes.

Raft 服务 / Raft Service​

RaftService 用于内部共识；请求中的 group_id 在单节点多 Raft 组时用于分解。

RaftService provides internal consensus RPCs. group_id demultiplexes multiple Raft groups on one node.

service RaftService {
    rpc AppendEntries(AppendEntriesRequest) returns (AppendEntriesResponse);
    rpc Vote(VoteRequest) returns (VoteResponse);
    rpc InstallSnapshot(stream SnapshotChunk) returns (SnapshotResponse);
}

客户端服务 / Client Service​

ClientService 提供写入、本地读、线性一致读和拓扑查询。

ClientService provides writes, local reads, linearizable reads, and topology discovery.

service ClientService {
    rpc Request(ClientRequest) returns (ClientResponse);
    rpc ReadLocal(ReadLocalRequest) returns (ReadLocalResponse);
    rpc ReadLinearizable(ReadLocalRequest) returns (ReadLocalResponse);
    rpc GetClusterInfo(Empty) returns (ClusterInfo);
}

IdempotencyError 包含 request_type、request_id、watermark；NamespaceLimitError 包含 request_type、request_id、namespaces、max。两者均与有效 payload 互斥，且 success=false。

IdempotencyError contains request_type, request_id, and watermark; NamespaceLimitError contains request_type, request_id, namespaces, and max. Both are mutually exclusive with meaningful payload and set success=false.

管理服务 / Admin Service​

节点状态、成员变更、快照、备份、路由与 formation 状态见 admin.proto；常用 RPC 的说明见 Admin API 参考。

See admin.proto for node status, membership, snapshots, backup, routing, and formation status; common RPCs are covered in the Admin API reference.

负载编码 / Payload Encoding​

  1. proto 层把业务数据与 Raft 内部状态视为不透明 bytes。

    The proto layer treats application data and internal Raft state as opaque bytes.

  2. Raft 内部数据使用 bincode v2 standard()；应用可选择 JSON、Protobuf 或其他业务编码。

    Raft internals use bincode v2 standard(); applications may choose JSON, Protobuf, or another encoding.

  3. 客户端原始字节可能由框架包装为 FramedEntry 或批处理帧，不再保证逐字节等同于 Raft 日志中的 payload；格式与版本规则见兼容性承诺。

    Raw client bytes may be wrapped in a FramedEntry or batch frame, so the Raft log payload is not guaranteed to be byte-for-byte identical. See the compatibility policy for framing and versioning rules.
