第 3 级：Cluster Admin Console 组件 / Level 3: Cluster Admin Console Components

本图展开 rr-admin console 的 Rust/Axum BFF。它与 Admin CLI/REPL 共用 rr-admin 二进制，并同源托管 Next.js 静态导出、connection-scoped JSON 和 SSE；无集群来源也可启动，每个显式连接的集群拥有独立 runtime， 生产环境不需要独立 Node.js 服务。

This diagram zooms into the Rust/Axum BFF started by rr-admin console. It shares the rr-admin binary with the Admin CLI/REPL and serves the Next.js static export plus connection-scoped JSON and SSE from one origin. It starts without a cluster source, gives every explicitly connected cluster an isolated runtime, and requires no standalone Node.js server.

同源入口与访问边界 / Same-Origin Entry and Access Boundary​

console.rs 组装监听器、可选 TLS、AuthState、profile/secret store 和 ConnectionManager。无 peers/discovery 时 manager 为空且不接触上游；http.rs 提供安全响应头、静态导出、连接 CRUD 和按 ID 解析的数据/SSE。完整 UI 来自随二进制部署的 console/out，也可用 --static-dir 指定。每个 runtime 复用缓存 change notification， 不会为每个浏览器创建上游采集循环。

console.rs assembles the listener, optional TLS, AuthState, profile/secret stores, and ConnectionManager. Without peers/discovery the manager is empty and contacts no upstream. http.rs provides security headers, static-export serving, connection CRUD, and ID-resolved data/SSE. The full UI comes from console/out, deployed with the binary or selected with --static-dir. Each runtime reuses cache change notifications rather than creating an upstream loop per browser.

viewer token 登录只创建 15 分钟内存 session；节点 Admin token 按连接留在 BFF 内。非 loopback 监听强制 Console HTTPS 和 viewer token。/connections/ 与 ?connection=<id> 让刷新、bookmark 和多 Page 独立选择 runtime； 不存在/断开的 ID 不会回退到默认集群。最多 8 个 runtime 活跃，Disconnect/Delete/进程退出停止其任务与 SSE。 本图没有 OIDC/RBAC 或多用户权限组件；多集群仍是单 operator 的只读客户端能力。

Viewer-token login creates only a 15-minute in-memory session, while each connection's node Admin token remains inside the BFF. Non-loopback listeners require Console HTTPS and a viewer token. /connections/ and ?connection=<id> give refresh, bookmarks, and multiple Pages independent runtime selection; unknown or disconnected IDs never fall back to a default cluster. At most eight runtimes are active, and Disconnect/Delete/process shutdown stops their tasks and SSE. OIDC, RBAC, and multi-user authorization are absent; multi-cluster remains a single-operator read-only client capability.

每连接调度、受信来源与证据视图 / Per-Connection Scheduling, Trusted Sources, and Evidence Views​

每个 Scheduler 是该连接浏览器请求和后台轮询共享的协调点：它合并 reconcile 与按需读取，限制并发，设置超时和 熔断，并从该 profile 的显式 seed 或可选 TrustedDiscovery 建立受信 roster。不同连接的 scheduler、cache、事件、 cursor 和 SSE 互不共享。discovery 通过同一 profile 的 etcd namespace 对 NodeDirectory 和 ConfigProvider 全量对账并监听变化；它不是 Raft membership 控制通道。

Each Scheduler coordinates browser requests and background polling for one connection. It coalesces reconciliation and on-demand reads, bounds concurrency, applies deadlines and circuit breakers, and builds a trusted roster from that profile's explicit seeds or optional TrustedDiscovery. Schedulers, caches, events, cursors, and SSE are not shared across connections. Discovery reconciles and watches NodeDirectory plus ConfigProvider in that profile's etcd namespace; it is not a Raft membership control channel.

TonicUpstream 只调用读取节点、拓扑、组、快照和 boot 证据的 Admin RPC。观测采集器仅从受信 observability_addr 抓取 /metrics、/health 和 /ready。ConsoleCache 与 metrics/model 逻辑负责身份和 能力降级、stale/partial 来源证据、组健康投影及有界事件/序列留存；实时趋势只存在内存中，重启即清空。

TonicUpstream invokes only Admin RPCs that read node, topology, group, snapshot, and boot evidence. The observability collector fetches /metrics, /health, and /ready only from trusted observability_addr origins. ConsoleCache and the metrics/model logic normalize identity and capability degradation, retain stale/partial source evidence, project group health, and bound event/series retention. Live trends are memory-only and disappear on restart.

可选 Prometheus 历史 / Optional Prometheus History​

配置保存连接的 Prometheus URL+精确 matcher（或 legacy 启动的成对 --prometheus-url 与 --prometheus-cluster）后，对应性能 handler 才通过 PrometheusHistoryClient 查询 /api/v1/query_range。 客户端生成固定 raw-family 模板并校验集群和节点映射；它不是任意 PromQL 代理。未配置 Prometheus 不影响该连接的 实时 CONSOLE_MEMORY、Admin 或 discovery 路径，也不会改变其他连接的历史配置。

A saved connection's Prometheus URL plus exact matcher (or the paired legacy --prometheus-url and --prometheus-cluster flags) enables its performance handler to call PrometheusHistoryClient at /api/v1/query_range. The client renders fixed raw-family templates and validates cluster and node mappings; it is not an arbitrary PromQL proxy. Omitting Prometheus does not disable that connection's live CONSOLE_MEMORY, Admin, or discovery paths, and does not change another connection's history configuration.

只读与故障边界 / Read-Only and Failure Boundaries​

POST /api/v1/console/connections/{id}/sources/reconcile 仅触发该连接共享调度器的只读刷新，并检查 CSRF 和同源 Origin。连接 CRUD/test/connect/disconnect/delete 也属于同源 mutation，但不执行 Raft 写操作。Console 不修改 membership、不强制选主、不触发快照、不 drain 节点、不 reset offset、不重启进程；受控写操作仍由 Admin CLI/REPL 执行。Console 是观测进程而非 Raft 控制面，停止或故障不会停止任何 Raft 节点。

POST /api/v1/console/connections/{id}/sources/reconcile only triggers a read-only refresh through that connection's scheduler, with CSRF and same-origin Origin checks. Connection CRUD/test/connect/disconnect/delete are also same-origin mutations but perform no Raft writes. The Console does not change membership, force leadership, trigger snapshots, drain nodes, reset offsets, or restart processes; controlled writes remain with the Admin CLI/REPL. It is an observation process, not a Raft control plane, so its failure does not stop any Raft node.

这里的 C4 Container 指浏览器应用、BFF 进程和节点服务等逻辑运行单元，不表示 Docker 容器。完整启动、安全、 来源与指标语义见集群管理控制台运维文档。

Here, a C4 Container means a logical runtime unit such as the browser application, BFF process, or node service, not a Docker container. See the Cluster Admin Console operations guide for startup, security, source, and metric semantics.
