边界与客户端行为 / Boundaries and Client Behavior​

  1. RaftService 与 ClientService 共享 listen_addr；Admin 使用可选的独立端口，observability 在 metrics_port 提供 /health、/ready 和 /metrics。

    RaftService and ClientService share listen_addr; Admin uses an optional separate port, and observability serves /health, /ready, and /metrics on metrics_port.

  2. RrClient 缓存 group leader；收到带 leader_info 的普通响应后更新缓存、退避并重试。

    RrClient caches group leaders; a normal response carrying leader_info updates the cache and triggers a backoff and retry.

  3. 没有独立网关；任何节点都可接收请求，非 leader 通过响应重定向客户端。

    There is no dedicated gateway; any node can receive a request, and a non-leader redirects the client.

  4. Console 静态前端与 BFF 是两个逻辑 C4 容器，但不是两个生产服务：CLI/REPL 与 Axum BFF 同属 rr-admin 二进制，Next.js 产物由 BFF 同源托管。部署需携带 console/out 或用 --static-dir 指向它，不需要独立 Node.js 服务。

    The Console static frontend and BFF are separate logical C4 containers, not separate production services: the CLI/REPL and Axum BFF share the rr-admin binary, and the BFF serves the Next.js export same-origin. Deploy console/out with the binary or select it with --static-dir; no standalone Node.js service is needed.

  5. Admin CLI/REPL 负责受控写操作；Console 只有 viewer 能力，连接 CRUD 只管理本地客户端配置， POST /connections/{id}/sources/reconcile 也只是该 runtime 的只读刷新，不执行 membership、强制选主、 TriggerSnapshot、DrainNode、offset reset 或进程重启。Console 不在 Raft/Client 数据路径上，其故障不影响节点服务。

    The Admin CLI/REPL owns controlled writes; the Console is viewer-only. Connection CRUD manages local client configuration, and POST /connections/{id}/sources/reconcile only refreshes that runtime's read-only evidence. Neither changes membership, forces leadership, triggers snapshots, drains nodes, resets offsets, or restarts processes. The Console is outside the Raft/Client data path, and its failure does not affect node service.

  6. 非 loopback Console 必须同时使用 HTTPS 和 viewer token；viewer session 仅保存在内存且 15 分钟过期。 一个 BFF 可保存多个 profile，但仅显式 Connect 的 runtime 采集，最多 8 个活跃；每连接的 Admin token 只留在 对应 BFF runtime。URL connection ID 隔离刷新、bookmark、多 Page、SSE 与晚到响应，不提供 OIDC/RBAC 或多用户权限。

    A non-loopback Console requires both HTTPS and a viewer token; viewer sessions are memory-only and expire after 15 minutes. One BFF can save multiple profiles, but only explicitly connected runtimes collect, with at most eight active. Each connection's Admin token remains inside its BFF runtime. URL connection IDs isolate refresh, bookmarks, Pages, SSE, and late responses; OIDC/RBAC and multi-user authorization are not provided.

  7. etcd discovery 与 Prometheus 历史均为可选；实时趋势来自 BFF 逐节点抓取并保存在有界内存中，重启即清空。

    Both etcd discovery and Prometheus history are optional. Live trends come from per-node BFF scrapes retained in bounded memory and are cleared on restart.
