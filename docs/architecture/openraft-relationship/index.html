与 openraft 的关系 / Relationship with openraft

Rr 不重新实现 Raft 算法，而是在 openraft 之上提供多共识组框架。

Rr does not reimplement Raft; it provides a multi-group consensus framework on top of openraft.

openraft 提供什么 / What openraft Provides​

openraft 是单共识组的 Raft 库，实现 Raft 论文 及其扩展：

openraft is a single-group Raft library implementing the Raft paper and its extensions:

  • 领导者选举、日志复制和安全性机制。
    Leader election, log replication, and safety machinery.
  • 联合共识成员变更。
    Joint-consensus membership changes.
  • 快照与日志压缩原语。
    Snapshot and log-compaction primitives.
  • ReadIndex 等线性一致读原语。
    Linearizable-read primitives such as ReadIndex.
  • 由使用方实现的 RaftLogStorage、RaftStateMachine、RaftNetwork / RaftNetworkFactory trait。
    The RaftLogStorage, RaftStateMachine, and RaftNetwork / RaftNetworkFactory traits implemented by the consumer.

openraft 提供一个组的引擎；存储、网络和部署形态由使用方补齐。

openraft supplies one group's engine; storage, networking, and deployment remain the consumer's responsibility.

封装方式 / How Rr Wraps openraft​

  • 类型配置：RrTypeConfig 通过 openraft::declare_raft_types! 绑定 Rr 的请求与响应类型。
    Type configurationRrTypeConfig uses openraft::declare_raft_types! to bind Rr's request and response types.
  • 节点封装：每组一个 RaftNode，持有 openraft::Raft<RrTypeConfig, RrStateMachine>。
    Node wrapperEach group has a RaftNode holding openraft::Raft<RrTypeConfig, RrStateMachine>.
  • 存储适配：RrLogStorage 实现 RaftLogStorage<RrTypeConfig>；RocksLogStorage 是 rocks feature 下的 RocksDB 实现。
    Storage adaptersRrLogStorage implements RaftLogStorage<RrTypeConfig>; RocksLogStorage is the RocksDB implementation behind rocks.
  • 状态机适配：RrStateMachine 把用户的 Service / StateMachine 接入 openraft 的 apply、snapshot 和 restore。
    State-machine adapterRrStateMachine bridges user Service / StateMachine implementations to openraft's apply, snapshot, and restore interfaces.
  • 网络适配：GrpcNetworkFactory 和实验性 TcpRaftNetworkFactory 实现 RaftNetworkFactory；快照通过 gRPC 流式 RPC 传输。
    Network adaptersGrpcNetworkFactory and experimental TcpRaftNetworkFactory implement RaftNetworkFactory; snapshots use streaming gRPC.
  • 组管理：RaftGroupManager 持有所有 RaftNode，提供写入、读取、成员变更和快照触发等组级 API。
    Group managementRaftGroupManager owns all RaftNodes and exposes group-level write, read, membership, and snapshot APIs.

版本锁定 / Version Pinning​

根 Cargo.toml 将 openraft 精确锁定为 = 0.10.0-alpha.34。pre-1.0 alpha 的相邻版本可能改变 API，精确锁定避免 cargo update 隐式升级；升级必须经过兼容性检查和测试。Rr 升级时以 reference/compatibility 为准。

The root Cargo.toml pins openraft to = 0.10.0-alpha.34. APIs can change between pre-1.0 alpha releases, so the exact pin prevents implicit upgrades through cargo update; upgrades require compatibility checks and tests. When upgrading Rr, consult reference/compatibility.

何时直接使用 openraft / When to Use openraft Directly​

以下场景可直接使用 openraft：

Use openraft directly when:

  • 单个共识组已足够，不需要分片。
    One consensus group is sufficient and no sharding is needed.
  • 需要最小依赖树，不接受 Rr 引入的 tonic、DashMap、metrics 等依赖。
    You need a minimal dependency tree without Rr's tonic, DashMap, metrics, and related dependencies.
  • 已有自研存储或传输层，需要完全控制这些边界。
    You already have custom storage or transport and need full control of those boundaries.
  • 需要持续跟踪 openraft 最新 API，而不是固定 alpha 版本。
    You need to track the latest openraft APIs rather than a fixed alpha release.

构建需要运维工具链的多分片强一致服务时，Rr 用部分底层灵活性换取集成后的多组框架。更多选型说明见 FAQ。

For a sharded, strongly consistent service that needs an operational toolchain, Rr trades some low-level flexibility for an integrated multi-group framework. See the FAQ for selection guidance.
