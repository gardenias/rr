## Summary

v1.0.0 is Rr's first stable major release. It establishes standard Semantic Versioning guarantees for the public Rust
API, gRPC wire protocol, configuration, CLI, durable formats, Console HTTP API, and metrics.

Since v0.2.0, Rr has gained durable Raft logs and state-machine snapshots, managed homogeneous cluster formation,
bounded decoding and other security hardening, outbox failover coverage, opt-in client write batching, multi-group
operation, deferred responses, an expanded Java SDK, and an independent multi-cluster Admin Console. The release also
includes extensive correctness fixes, local quality gates, performance baselines, fault injection, crash recovery,
fuzzing, property tests, and TLA+ models.

## Highlights

- **Stable 1.0 compatibility contract.** Within MAJOR 1, public APIs and wire fields follow additive MINOR and PATCH
  evolution; breaking changes require a new MAJOR. See the compatibility policy and migration guide before upgrading.
- **Durability and correctness.** Production binaries persist both Raft logs and state-machine snapshots. Snapshot
  writes are atomic and fail closed, shutdown drains pending I/O, and client reads and writes no longer fake success
  when the leader is unknown.
- **Managed formation and topology.** Genesis initializes a fresh homogeneous roster through a linearizable lifecycle
  store; Adopt records legacy clusters before explicit membership convergence. Runtime descriptors, boot journals,
  topology, formation status, and per-group evidence are observable through Admin and Console.
- **Security hardening.** TLS/mTLS, bearer authentication, startup security gates, bounded RPC/frame decoding,
  rate-limit fixes, audit events, sanitized errors, and fail-closed idempotency/offset handling are included.
- **Rust and Java clients.** Both SDKs handle leader redirects and deterministic failures without fake success. Rust
  adds opt-in byte-aware write batching, request timeouts, linearizable reads, and channel fanout; Java adds reactive
  and blocking APIs, request deadlines, TLS/mTLS, metrics, and typed failures.
- **Multi-cluster Admin Console.** One read-only `rr-admin console` process manages multiple explicit cluster
  connections with isolated HTTP/SSE state, persistent non-sensitive profiles, OS-keychain-backed optional secret
  storage, CSRF/origin protection, nine resource views, and responsive accessible UI.
- **Local full-observation workflow.** `just kv-console-cluster-up` starts a three-node Genesis + Rocks KV cluster with
  explicit descriptors, per-node metrics, persistent boot journals, and a seeded Console. `just console-up` also starts
  a standalone Console.
- **Measured performance improvements.** Removing the default timed group-commit window improved measured RocksDB
  strict serial writes from roughly 0.4k to 4831 TPS on the recorded reference setup. Opt-in batch64 + fanout4 reached
  169.3k TPS with RocksDB strict and 174.2k TPS with memory storage in November 2026 single-host loopback benchmarks. These
  are measurements, not SLAs.

## Breaking Changes and Upgrade

Read the
[migration guide](https://github.com/gardenias/rr/blob/v1.0.0/docs/docs/deployment/v0.2-to-v1.0-migration.md)
before upgrading. The main changes are:

- Stock v0.2.0 keeps Raft logs in memory, so its offline single-node backups cannot reconstruct a cluster. Use the
  guide's side-by-side application migration: fence old-cluster writes before the final consistent export, and keep the
  old cluster running and write-fenced through cutover and the rollback window. No generic in-place rolling or
  backup/restore upgrade is claimed.
- Legacy `DurabilityPolicy::Balanced` / `Fast` aliases and their configuration strings are removed.
- v1.0.0 uses versioned snapshot/membership envelopes in the new cluster. Released v0.2.0 does not contain
  `SnapshotStore`; interim-build formats require a deployment-specific recovery runbook.
- `LinearizableReadResult` is an explicit `Served` / `NotLeader` enum.
- `RouterError::GroupNotFound` was removed, several public error signatures changed, and generated Admin descriptor
  fields are now named `node_descriptor` (field number and wire encoding unchanged).
- Configuration validation is stricter for gRPC frame/stream limits and Kafka topic patterns. MemConfigProvider
  removal/conflict semantics are now explicit and loud.

The full, dated technical breakdown is in [`CHANGELOG.md`](https://github.com/gardenias/rr/blob/v1.0.0/CHANGELOG.md).

## Install

Rust dependencies should use the patched source tag so the workspace's vendored openraft fixes remain in effect:

```toml
[dependencies]
rr-client = { git = "https://github.com/gardenias/rr.git", tag = "v1.0.0" }
rr-core   = { git = "https://github.com/gardenias/rr.git", tag = "v1.0.0" }
rr-raft   = { git = "https://github.com/gardenias/rr.git", tag = "v1.0.0" }
rr-server = { git = "https://github.com/gardenias/rr.git", tag = "v1.0.0" }

# Required: Rr's workspace patch is not inherited by downstream projects.
[patch.crates-io]
openraft = { git = "https://github.com/gardenias/rr.git", tag = "v1.0.0" }
```

Use Rust 1.98 or newer and align public dependency versions with the consumer guide. Keep the explicit openraft patch
and verify it with `cargo tree -i openraft`; otherwise Cargo selects the unpatched registry package. This source release
does not claim crates.io publication.

The Java SDK source version is `1.0.0`. The Helm chart and raw Kubernetes manifests pin application/image version
`1.0.0`. Registry and package-repository publication are separate artifact-distribution steps and are not implied by
the source tag.

## Known Limits and Operational Notes

- The exact pinned openraft dependency remains `0.10.0-alpha.34`; use the source tag to retain Rr's vendored patches.
- The experimental TCP Raft transport remains loopback-only and is not the production default.
- Managed formation does not provide dynamic expansion, replica replacement, or resharding. SeedSpec is an initial
  roster, not current Raft membership.
- Performance results depend on host, storage, workload, and opt-in features; fixed-host multi-group aggregate
  throughput does not scale merely by adding groups.

## Release Verification

The release cut uses local verification because hosted CI is not part of this release process. The following gates
passed on the release content:

- `just check && just gate-test` — workspace formatting, invariants, all-target compilation, and complete tests.
- `just build-release` — optimized workspace binaries and Console static export; `rr-server version` reports 1.0.0.
- `cargo semver-checks check-release --workspace --exclude openraft --baseline-rev v0.2.0` — all Rr packages passed.
  Vendored openraft is excluded because it has an independent upstream version and does not exist in the v0.2.0 baseline.
- `just java-build` — Java compilation, unit/integration test tasks, Javadoc, sources, and JAR assembly.
- `just helm-test` — 17 static/render tests, including secure adoption Job authentication.
- `just console-test` — 187 unit tests and 71 browser tests.
- `just docs-build` — Docusaurus production build.
