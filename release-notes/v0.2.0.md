## Summary

v0.2.0 is rr's first production-grade release. It builds on the v0.1.0
multi-Raft framework with a fixed correctness contract, the deployment
machinery needed to actually run rr in production, and the
observability surface needed to operate it.

The release fixes three correctness gaps inherited from Phase 2 — the
RocksDB durability bug, panic-on-init crashes, and one-directional
fault isolation in chaos tests — and adds everything required to ship
rr clusters: a real `rr-server` binary, TLS / mTLS, bearer-token auth,
per-service rate limiting, audit logging, Docker images, K8s manifests,
a Helm chart, offline backup tooling, HTTP observability endpoints,
W3C trace-context propagation, five operational runbooks, and a full
C4 architecture diagram suite.

On top of the rc2 content, the final tag folds in four more waves of
work: the **Phase 4 framework features** (linearizable client reads via
ReadIndex, outbox / side-effect delivery, configurable snapshot
strategy, per-caller rate limiting, per-CF RocksDB tuning), the
**release-hardening batch** (shutdown durability contract,
change-membership quorum guard, TCP transport security gate,
`GroupMeta.leader` removal, fail-closed offset mapping, client
fake-success fix), a **server-side latency-budget metrics suite**
(request → proposal → apply, replication RTT, ingestor commit
counters), and the **reliability program R-1~R-8** — an invariant
registry enforced in CI, property-based tests, fuzz corpora, a
process-level crash-recovery harness, storage fault injection, a
porcupine-style linearizability checker, seeded fault-schedule replay,
soak automation, performance baselines with regression gates, and four
TLA+ specifications of rr's extension protocols checked counterexample-
free by TLC.

## Highlights

- **RocksDB durability bug fixed.** Pre-v0.2.0 RocksDB neither called
  `set_sync(true)` nor `set_use_fsync(true)`, silently violating Raft's
  durability contract. v0.2.0 introduces explicit
  `DurabilityPolicy { Strict, Balanced, Fast }` with `Strict` as the
  default. **All v0.1.0 deployments should upgrade.**
- **`rr-server` is now a real binary**, not a 4-line stub. Full clap
  CLI + TOML config + env var overrides + SIGTERM/SIGINT graceful
  shutdown + a built-in `EchoStateMachine` for smoke testing.
- **TLS / mTLS via rustls** with optional client-cert verification, plus
  **bearer-token auth** with constant-time comparison and **per-service
  rate limiting** (admin & client; **never Raft** — by design).
- **Deployment artifacts**: multi-stage Docker image
  (`ghcr.io/gardenias/rr`, non-root UID 10001), docker-compose for local
  3-node clusters, raw K8s manifests with StatefulSet + PDB, and a Helm
  chart at `oci://ghcr.io/gardenias/charts/rr`.
- **HTTP observability**: a single hyper server on `metrics_port`
  exposes `GET /health` (liveness), `GET /ready` (readiness), and
  `GET /metrics` (Prometheus). K8s manifests use HTTP probes.
- **Audit log + W3C traceparent passthrough**: structured admin-RPC
  events on the `rr::audit` tracing target, plus traceparent /
  tracestate propagation on inbound RPCs (no OpenTelemetry SDK bundled
  — bring your own).
- **Offline backup / restore** in `rr-admin`, plus **five operational
  runbooks** covering disk-full, leader-flapping, network partitions,
  snapshot corruption, and ConfigProvider unreachability.
- **Shutdown durability contract (ADR A-0011)**: `IoBatcher` is a
  tracked spawn with an explicit `close()` protocol (drain → final
  fsync → answer pending → join), and `stop_group` awaits the flush —
  acknowledged writes survive a graceful shutdown, verifiably.
- **change-membership quorum guard (ADR A-0012)**: the server rejects
  membership changes that would drop below 2 voters, and never permits
  removing down to 0 — with an audited `force` escape hatch.
- **Linearizable client reads (ADR A-0009)**: a dedicated
  `ClientService.ReadLinearizable` RPC backed by openraft ReadIndex,
  with leader-aware redirects handled transparently by the SDK.
- **Log-visibility contract fix (ADR A-0015, critical)**: the crash
  harness caught async append violating openraft's "submitted ⇒
  visible" contract — release builds could silently skip applies and
  diverge replicas. Fixed with a pending overlay + flush barrier in
  the RocksDB log storage.
- **Reliability engineering R-1~R-8**: invariant registry linted in CI,
  proptest suites, fuzz corpora with a nightly workflow, a SIGKILL
  crash-recovery harness with an ack-log oracle, storage fault
  injection, a linearizability checker, seeded fault replay, soak
  automation, performance regression gates, and TLA+ models of the
  membership guard, exactly-once offset chain, output watermark, and
  routing-table switch — all counterexample-free.

## Security

### TLS and mTLS via rustls

`rr_network::tls::TlsConfig` exposes a typed configuration for gRPC
over rustls (tonic feature `tls-ring`). Each node may opt in
independently. `rr_raft::network_factory::TlsPaths` mirrors the same
shape on the outbound side, and `ChannelPool::with_tls` dials peers
over `https://` with client certs. New CLI flags:

```
--tls-cert PATH --tls-key PATH --tls-ca PATH
--tls-domain HOST --tls-require-client-cert
```

Mirrored env vars and a `[tls]` config-file section are also supported.
A `scripts/gen-dev-certs.sh` script generates a self-signed CA + per-node
certs (SANs cover `localhost`, `127.0.0.1`, `rr-N`, `nodeN.rr.local`)
for local development. Full guide:
[`docs/deployment/tls.md`](https://github.com/gardenias/rr/blob/v0.2.0/docs/docs/deployment/tls.md).

### Bearer-token authentication

`rr_network::auth` provides `AuthConfig`, `BearerInterceptor`, and
`attach_bearer_token`. AdminService and ClientService each carry their
own token (cannot be the same value). RaftService is intentionally
authenticated **only** via mTLS — bearer tokens on every Raft RPC would
add per-message overhead on the cluster's hot path. Token comparison
uses constant-time equality (backed by the vetted `subtle` crate) to
defeat timing attacks. Tokens are loaded from environment variables
referenced by name in `[auth]`; they are never written into config
files on disk.

### Per-service rate limiting

`rr_network::rate_limit` ships a token-bucket limiter built on
`tokio::sync::Semaphore` with **zero new dependencies**. `RateLimitConfig`
exposes `admin_rps`, `client_rps`, and `burst`. `ChainedInterceptor`
composes auth (cheap fail-fast) before rate-limit (only counts
authenticated requests). On exhaustion, gRPC returns
`RESOURCE_EXHAUSTED`. **`RaftService` is structurally exempt**: there
is no API path to rate-limit it, because throttling Raft RPCs
destabilises consensus. New CLI flags `--admin-rps`, `--client-rps`,
`--rate-limit-burst`; matching env vars; `[rate_limit]` config section.
Optional **per-caller** buckets (ADR A-0005) key the limiter on the
authenticated caller's token fingerprint.

### Audit log

The `rr::audit` tracing target emits a structured info-level event for
every AdminService RPC, with `op`, `peer` (socket addr), `node_id`,
and per-operation fields. Mutation RPCs emit both dispatch and result
events for forensic pairing, and auth / rate-limit rejections are
audited per-reject. Schema and routing recipes:
[`docs/deployment/audit-log.md`](https://github.com/gardenias/rr/blob/v0.2.0/docs/docs/deployment/audit-log.md).

### Startup security gates

`RrNode::new` refuses to start when any of five gates is violated —
RaftService without TLS, RaftService without mTLS, bearer auth without
TLS, AdminService without TLS, or AdminService without `admin_token` —
aggregating all violations into one error. A `RaftTransport::Tcp`
selection adds two more gates (ADR A-0014): TCP requires explicit
`allow_insecure`, and the bind address must be loopback (not
bypassable). For dev / CI there is an opt-in `allow_insecure` escape
hatch that logs a structured warning and sets the
`rr_security_insecure_mode = 1` gauge. The shipped K8s manifests and
Helm chart default to a configuration that passes these gates; Helm
refuses to render an insecure combination unless
`security.allowInsecure=true` is set explicitly.

## Operations

### Production `rr-server` binary

Replaces the 4-line stub from v0.1.0 with a full clap CLI exposing
`serve` and `version` subcommands. Configuration layers in this
precedence order: **CLI flags > env vars > TOML file > defaults**, with
`deny_unknown_fields` strict parsing. Sections cover `[node]`,
`[storage]`, `[cluster]`, `[tls]`, `[auth]`, and `[rate_limit]`.
SIGTERM and SIGINT trigger graceful shutdown with bounded timeouts.
A built-in `EchoStateMachine` is included for smoke testing.
Three example configs live in `examples/config/`.

### Deployment artifacts

- **Multi-stage `Dockerfile`** (Debian slim, non-root `rr:rr` at
  UID 10001), with a `HEALTHCHECK` against `/ready`.
- **`docker-compose.yml`** for a local 3-node cluster, with
  healthcheck-gated startup ordering.
- **Raw K8s manifests** at `deploy/k8s/statefulset.yaml`: StatefulSet,
  headless Service, client Service, PodDisruptionBudget, pod
  anti-affinity, and TLS/token wiring that passes the startup gates.
- **Helm chart** at `deploy/helm/rr/` with TLS, auth, and storage
  knobs in `values.yaml`, plus the `security.allowInsecure` guard.
- **`.github/workflows/release.yml`** publishes the Docker image to
  `ghcr.io/gardenias/rr` and the Helm chart (OCI) to
  `ghcr.io/gardenias/charts/rr` on every tag push, plus an optional
  crates.io publish step gated on `workflow_dispatch`.
- **K8s deployment guide** with a cert-manager TLS example:
  [`docs/deployment/kubernetes.md`](https://github.com/gardenias/rr/blob/v0.2.0/docs/docs/deployment/kubernetes.md).

### Offline backup / restore

`rr-admin` now exposes `backup` / `restore` / `inspect-backup`
subcommands. Backups are gzip-compressed tar archives containing a
`metadata.json` descriptor and the node's `data_dir`. The format is
explicitly versioned (`format_version = 1`); restore refuses newer
major versions. Six unit tests plus an end-to-end roundtrip cover
this surface. Backups are **offline** — the node must be stopped.
An **online** backup path (`AdminService.OnlineBackup` streaming RPC +
`rr-admin online-backup --group N --output PATH`, fetching the latest
committed snapshot from a running node, with `--force-fresh` to trigger
a fresh snapshot first) landed after `v0.2.0-rc2` and is included in
this release — see the `[0.2.0]` section of the CHANGELOG.

### Five operational runbooks

Under `docs/operations/runbooks/`:

- **disk-full** — recovery when RocksDB exhausts the volume.
- **leader-flapping** — diagnosing rapid term churn.
- **network-partition** — handling minority partitions.
- **snapshot-corruption** — repairing a corrupt snapshot file.
- **configprovider-unreachable** — operating with a downed config source.

Each follows the structure: Symptom → Detection → Immediate mitigation
→ Root cause → Recovery → Prevention.

### C4 architecture diagram suite

[`docs/architecture/c4/`](https://github.com/gardenias/rr/blob/v0.2.0/docs/docs/architecture/c4/README.md)
contains 13 C4-PlantUML diagrams covering Context, Container, four
Component levels (server, raft, router, network), Deployment, and five
Dynamic flows (PUT request, leader election, snapshot transfer, shard
routing, config update). The previous Mermaid diagrams were converted
to PlantUML for richer rendering and removed
`@docusaurus/theme-mermaid` from the docs site.

## Observability

### HTTP `/health`, `/ready`, `/metrics` endpoints

`rr_server::health` runs a single hyper server on `metrics_port`
serving:

- `GET /health` — liveness, returns 200 unconditionally.
- `GET /ready` — readiness, returns 200 once `start()` completes,
  503 otherwise. Driven by a shared `ReadinessFlag` that is flipped
  to `true` at the end of `start()` and back to `false` on
  `shutdown()`.
- `GET /metrics` — Prometheus exposition format.

K8s manifests now use HTTP probes on this endpoint instead of TCP-on-
gRPC-port, because TCP liveness on gRPC cannot distinguish
"server accepting connections" from "cluster can make progress".
A new integration test covers the full lifecycle of all four routes.

### W3C Trace Context propagation

`rr_network::tracing` provides `extract_traceparent`, `extract_tracestate`,
`attach_traceparent`, and `attach_tracestate` helpers. Inbound RPC
handlers log the incoming traceparent on the tracing span for
cross-service correlation. **The OpenTelemetry SDK is intentionally
not bundled** (~12 MB of transitive deps) — users bring their own OTLP
stack. `#[instrument]` covers `ClientDispatchImpl`,
`RaftGroupLookupImpl`, and `RrClient::send_request*` for full span
coverage on the hot paths.

### Client-side metrics

`rr-client` now emits four metrics, all labelled with `group_id`:

- `rr_client_request_duration_seconds` (histogram, with
  `outcome=success|failure`)
- `rr_client_retries_total` (counter)
- `rr_client_leader_cache_hits_total` / `_misses_total` (counters)

These complement the existing 14 server-side metrics (previously only
six were documented; full reference now in
[`docs/reference/metrics-reference.md`](https://github.com/gardenias/rr/blob/v0.2.0/docs/docs/reference/metrics-reference.md)).

### Latency-budget metrics suite

The server-side latency budget is now closed (`server ≈ routing +
replication + apply`): `rr_server_requests_total{group_id,op,outcome}`
+ `rr_server_request_duration_seconds{group_id,op}` at the
client-protocol boundary, `rr_raft_apply_duration_seconds` +
`rr_raft_applied_entries_total` at the state-machine adapter (an exact
applied-TPS source), `rr_raft_append_entries_rtt_seconds{kind}` for
leader→follower RTT, and `rr_ingestor_commands_committed_total` for
the Kafka path. Histograms export as native Prometheus histograms via
explicit buckets; recording rules and the Grafana cluster-overview
dashboard are rebuilt around the budget.

## Reliability

### RocksDB durability fix &nbsp;_(critical correctness fix)_

Pre-v0.2.0, `RocksConfig::default()` did not configure fsync on the
WAL, which meant a power failure could lose committed Raft entries —
a violation of Raft's durability contract. This release introduces
explicit `DurabilityPolicy { Strict, Balanced, Fast }`:

- **`Strict`** — `set_sync(true)` + `set_use_fsync(true)`. **New default.**
- **`Balanced`** — fsync per batch but not per write.
- **`Fast`** — no fsync. For tests only;
  `RocksConfig::for_testing()` uses this.

`RocksStorage::put` / `delete` / `write_batch` now use `*_cf_opt` /
`write_opt` variants with `WriteOptions` driven by the chosen policy.
**All v0.1.0 deployments should upgrade.** (The policies were renamed
to `Strict` / `ReplicatedOnly` / `TestOnly` post-rc2 — the old names
remain as deprecated aliases until v0.3.0; see Breaking Changes.)

### `RaftNode::new_*` returns `Result` instead of panicking

`RaftNode::new_with_factory`, `::new_single_node`, and
`::new_with_rocks_factory` now return `Result<Self, RrError>` instead
of panicking on config validation or RocksDB open failure. A new
`RaftError::InitializationFailed { reason }` variant carries the cause.
This removes a class of production crashes where a node would panic
on startup instead of surfacing a clean error.

This is a **breaking change** for direct callers (all 27 internal
call sites have been updated). Library users who already propagate
errors via `?` need no change.

### Bidirectional fault isolation in chaos tests

Pre-v0.2.0, `FaultAwareChannelPool` only blocked **inbound** traffic to
isolated nodes. The leader could still send heartbeats outbound, so
`test_leader_isolation_and_recovery` could never trigger a leader
step-down and four chaos tests were forced behind `#[ignore]`. This
release refactors the harness to per-node pools sharing a common
`FaultState`, making isolation **bidirectional**. All four chaos
tests — `test_leader_isolation_and_recovery`,
`test_follower_isolation_and_catchup`,
`test_packet_loss_convergence`,
`test_latency_under_high_load` — now run in the default CI test job.

### Reliability engineering program (R-1~R-8)

Every property this release advertises — durable append, exactly-once
apply, linearizable reads, safe membership change, ordered output
delivery, routing-table convergence — now has an enforced invariant
chain behind it:

- **R-1 invariant registry**: `docs/reference/invariants.md` + a
  bidirectional lint (`scripts/check-invariants.sh`, blocking CI job)
  keeping registry ↔ code ↔ tests linked.
- **R-2 TLA+ formalization** (`formal/tla/`): four specs covering the
  membership guard, the offset exactly-once chain, the output
  watermark, and the routing-table switch — all checked
  counterexample-free by TLC, with planted-bug specs proving the
  models bite. A weekly CI workflow reruns them.
- **R-3 deterministic fault replay**: seeded fault schedules recorded
  to JSONL and replayable verbatim in the chaos suite (a turmoil-based
  full simulation was spiked and deferred per the time-box; the
  re-evaluation triggers are documented).
- **R-4 crash-recovery harness + storage fault injection**: real
  SIGKILL/SIGTERM cycles against a 3-node RocksDB/strict cluster with
  an fdatasync ack-log oracle (nightly workflow), plus a programmable
  `FaultInjectingStorage` wrapper (fail fsync, torn writes, ENOSPC,
  latency).
- **R-5 linearizability checker**: porcupine-style register checker
  consuming real histories recorded from the chaos tests, with
  counterexample minimization.
- **R-6 property tests + fuzz**: proptest suites for router
  transitions, the idempotency LRU/watermark, IoBatcher interleavings,
  and the framed-codec version matrix (plus a golden byte corpus);
  fuzz targets with an in-repo seed corpus and a nightly workflow.
- **R-7 performance baseline + regression gates**: first release-mode
  baseline archived (`docs/perf/baselines/`, ~34k TPS saturated on the
  reference machine); criterion baseline comparison runs in CI with
  significance thresholds.
- **R-8 soak automation**: `scripts/soak.sh` drives a 3-node lab
  cluster under a seeded fault loop with a three-part oracle (no loss,
  no panic, lag convergence); a nightly smoke soak runs in CI.

The crash harness paid for itself immediately: it caught **ADR A-0015**,
a critical log-visibility violation (async append racing openraft's
"submitted ⇒ visible" contract) that could silently fork replica state
machines in release builds. The fix (pending overlay + flush barrier)
ships in this release with regression coverage.

### Architecture documentation accuracy

The C4 component diagrams previously described `RrGrpcServer` (a
Phase 2 scaffolding stub) as the gRPC server entry point. The stub
was never wired into production — `RrNode::start()` always called
`tonic::transport::Server::builder()` directly. This release deletes
the stub (see Breaking Changes), updates seven architecture documents
to reflect the actual server lifecycle, and corrects the previously-
inaccurate "three services on one tonic Server" claim with the actual
**dual-server topology**: `RaftService` + `ClientService` + `Health`
share the main port (`listen_addr`); `AdminService` runs on a separate
`tonic::Server` bound to `admin_port` so admin traffic cannot starve
consensus bandwidth.

## Breaking Changes

The following changes require code updates when upgrading from v0.1.0.

### `RaftNode::new_*` now returns `Result`

```rust
// v0.1.0 — could panic on init
let node = RaftNode::new_with_factory(...);

// v0.2.0 — must propagate or handle the Result
let node = RaftNode::new_with_factory(...)?;
```

### `rr_network::{client, server}` modules removed

The `RrGrpcClient` and `RrGrpcServer` types in those modules were
Phase 2 scaffolding stubs that no production code path ever
instantiated (verified via grep across the workspace). They have been
deleted along with their `pub mod` and `pub use` re-exports.

If you have an external crate depending on these symbols, the cleanest
fix is to use `tonic::transport::Server::builder()` directly (which is
what `RrNode::start()` does internally). See
[`docs/architecture/c4/components-server.md`](https://github.com/gardenias/rr/blob/v0.2.0/docs/docs/architecture/c4/components-server.md)
for the canonical pattern.

### MSRV bumped from 1.82 to 1.98

The 1.88 step (at rc2) was required by transitive dependencies:
`clap_lex ≥ 1.1.0` needs the `edition2024` feature stable in Rust
1.85, and `validit 0.2.5` uses `let_chains` stable in Rust 1.88; the
final tag moves to 1.98. A pinned `rust-toolchain.toml` is included so
`cargo` auto-installs the right toolchain on first invocation.

### `RocksConfig::default()` is now `DurabilityPolicy::Strict`

The previous implicit "Fast" behaviour (no fsync) violated Raft's
durability contract. The new default trades roughly an order of
magnitude in write throughput for actually persisting committed
entries across power loss. If you really want the old behaviour for
tests, use `RocksConfig::for_testing()`.

### `DurabilityPolicy` variants renamed

`Balanced` → `ReplicatedOnly` and `Fast` → `TestOnly`, to say what
they mean. The old names remain as `#[deprecated(since = "0.2.0")]`
aliases (TOML / CLI accept the old strings with a startup warning) and
are **removed in v0.3.0** — migrate before then.

### `GroupMeta.leader` removed (ADR A-0013)

The volatile raft-runtime leader no longer lives in the static routing
table. Also removed: `ShardRouter::get_leader` / `get_leader_addr`,
`RouterError::NoLeader`, and the `router.get_leader_addr.success`
metric. Leader discovery is exclusively the client SDK's redirect
cache fed by `NotLeader { leader_addr }` / `leader_info`. Stored
routing data (etcd) needs **no migration** — `leader` was derived at
read time and legacy JSON carrying it is silently ignored.

### Public error enums are `#[non_exhaustive]`

`RrError`, `RaftError`, `StorageError`, `ConfigError`, `RouterError`,
`NetworkError`, `CodecError` (plus `ServiceLabel`, `RaftTransport`,
`SecurityProtocol`, `KafkaIngestorError`, `KafkaOffsetError`) are now
`#[non_exhaustive]`: downstream `match` statements need a wildcard
arm. This is what lets post-0.2.0 patch releases add variants without
a breaking change.

### `OffsetToRequestId` / `kafka_offset_to_request_id` return `Result`

Undecodable offset bytes and negative sentinels are now fail-closed
(the ingestor supervisor exits with an error) instead of silently
mapping to `0`, which broke the exactly-once guarantee. Callers must
handle the `Result`.

### `openraft` migrated `0.10.0-alpha.19` → `0.10.0-alpha.34`

Adapts to the `SnapshotData` move, `snapshot_id` removal from
`SnapshotMeta`, and `Trigger::elect(pre_vote)`, and inherits upstream
fixes (commit-safety #1802, snapshot membership divergence #1808,
RaftCore stalls #1810). Rolling-upgrade note: vote RPCs from
pre-upgrade nodes fail to decode on upgraded nodes — upgrade the
leader last and avoid elections mid-roll.

### Behavioural tightenings worth knowing about

- **rr-client never fake-succeeds in the leader-unknown window**:
  `success=false` responses are always retried; exhausted attempts
  return `RaftError::NotLeader` instead of `Ok` with an empty payload.
- **Blocking client APIs preflight their runtime**: the `*_blocking`
  methods return a typed error on `current_thread` / no runtime
  instead of panicking.
- **`ResolvedConfig::resolve` returns typed `ConfigError`** (was
  `anyhow::Result`).
- **`token_fingerprint` widened to 64-bit (16-hex)**: the
  `caller_token_fp` field in auth-reject audit events changes format
  (was 8-hex).
- **Metrics**: `rr_snapshot_installs_total` is now correctly labelled
  with `group_id`; `rr_proposal_duration_seconds` gained a `source`
  label; auth-interceptor constructors take a `ServiceLabel`.
- **Error sanitization**: gRPC error responses no longer leak peer
  addresses, openraft internals, or storage paths to clients (detail
  stays in server logs).

## Upgrading from v0.1.0

The minimal upgrade path:

1. **Bump the rr dependency** in your `Cargo.toml` — the
   [consumer guide](https://github.com/gardenias/rr/blob/v0.2.0/docs/docs/guide/consumer-guide.md)
   covers all three consumption modes.
2. **Install Rust 1.98+** (the bundled `rust-toolchain.toml` will do
   this automatically on the next `cargo` invocation).
3. **Adapt `RaftNode::new_*` callers** to propagate the new `Result`
   via `?` or an explicit `match`. Most callers already use `?`
   inside an outer `Result` and need no change.
4. **Drop `use rr_network::{RrGrpcServer, RrGrpcClient}`** if your
   code referenced them. Replace with direct
   `tonic::transport::Server::builder()` usage.
5. **Audit your RocksDB write throughput**. The new `Strict` default
   is roughly 10× slower than the old implicit "Fast" behaviour —
   that's the cost of actually being durable. If your workload tolerates
   relaxed durability (e.g. replicated data with periodic backups),
   you can opt down to `DurabilityPolicy::ReplicatedOnly` explicitly.
6. **Rename `DurabilityPolicy::Balanced` / `Fast`** to
   `ReplicatedOnly` / `TestOnly`. The deprecated aliases compile until
   v0.3.0, but migrating now avoids the hard break then.
7. **Handle `#[non_exhaustive]` error enums** — add a wildcard arm to
   any downstream `match` on rr error types.
8. **Stop reading `GroupMeta.leader`** if you consumed the routing
   table directly; leader discovery belongs to the client SDK's
   redirect cache.
9. **Migrate to the dedicated `rr-server` binary** if you were running
   examples in production. The `rr-server` binary exposes a richer
   config surface and proper graceful shutdown.

The data on disk from v0.1.0 RocksDB stores is forward-compatible —
no offline migration is required.

## Install

### Docker

```bash
docker pull ghcr.io/gardenias/rr:v0.2.0
```

Run with the example config:

```bash
docker run --rm -v $PWD/examples/config/single-node.toml:/etc/rr/config.toml \
  -p 51001:51001 -p 9100:9100 \
  ghcr.io/gardenias/rr:v0.2.0 serve --config /etc/rr/config.toml
```

### Helm

```bash
helm install rr oci://ghcr.io/gardenias/charts/rr --version v0.2.0
```

See [`deploy/helm/rr/values.yaml`](https://github.com/gardenias/rr/blob/v0.2.0/deploy/helm/rr/values.yaml)
for the full set of knobs.

### Cargo (downstream Rust projects)

While rr is not yet on crates.io, the recommended path is `git+tag`:

```toml
[dependencies]
rr-client = { git = "https://github.com/gardenias/rr.git", tag = "v0.2.0" }
rr-core   = { git = "https://github.com/gardenias/rr.git", tag = "v0.2.0" }
```

Full setup including private-repo SSH and `net.git-fetch-with-cli`:
[`docs/guide/consumer-guide.md`](https://github.com/gardenias/rr/blob/v0.2.0/docs/docs/guide/consumer-guide.md).
